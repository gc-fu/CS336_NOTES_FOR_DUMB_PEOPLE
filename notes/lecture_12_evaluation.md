### 0.2 这讲只问一件事

视频 [00:05](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=5s) 开门见山：今天讲 evaluation（评估）。**Evaluation** 是用一套明确规则收集证据，判断模型、方法或完整系统在某个目标上表现怎样。

最重要的一句话：

> “好”是抽象概念；分数只是把其中一个具体方面变成可测数字。分数不是模型的“真实智力”。

全讲因果链：

1. 先写清想知道的抽象问题，例如“能否帮程序员修真实 bug”。
2. 再把它变成任务、样本、运行规则和 metric（指标）。
3. 检查指标是否真的代表目标，而不只是容易计算。
4. 检查模型能否通过污染、风格、预算或测试漏洞刷高分。
5. 报告不确定性、成本、适用人群和失败案例。
6. 最后才用证据做采购、研究或部署决定。

### 0.3 先认识十二个词

- **Model（模型）**：把输入映射成输出的参数化程序，例如只给 prompt 生成文字的语言模型。
- **Method（方法）**：训练或推理的办法，例如新 optimizer、数据配方或解码算法。
- **System（系统）**：模型加 prompt、检索、工具、记忆、重试和程序逻辑的整体。
- **Benchmark（基准测试）**：固定的一组任务和评分规则，用来比较系统。
- **Metric（指标）**：把表现变成数字的规则，如 accuracy 或平均耗时。
- **Accuracy（准确率）**：答对数除以总题数。80 题答对 60 题，就是 $`60/80=0.75=75\%`$。
- **Construct（构念）**：真正想研究但不能直接摸到的抽象对象，如“医学帮助能力”。
- **Proxy（代理指标）**：用来近似构念的可测数字；选择题准确率可能是知识能力的 proxy。
- **Dataset（数据集）**：按某种规则收集的样本集合。
- **Distribution（分布）**：什么样的样本常见、各自出现多大概率的总体规律。
- **Baseline（基线）**：用于比较的简单参考方法，如随机猜。
- **Snapshot（快照）**：只代表某个日期、模型集合和规则的结果，不是永远不变的事实。

### 0.4 一个指标的最小结构

假设要评“是否会两位数加法”：

1. construct：两位数加法能力；
2. sample：`27+35`；
3. response：模型回答 `62`；
4. reference：标准答案 `62`；
5. scoring rule：完全相等计 1，否则 0；
6. aggregation：100 题得分取平均；
7. protocol：不许工具、temperature=0、每题只答一次；
8. uncertainty：换一批题是否还差不多。

少写任何一项，别人都可能无法公平复现。

## 1. 五分钟复习卡（首次阅读跳过）

1. Evaluation 是“目标→任务→规则→指标→解释”的链，不是只算一个分数。（§2）
2. 能力、成本、人类偏好和实际采用率是不同轴，不能揉成唯一真分数。（§2）
3. $`PPL=\exp(\text{平均 NLL})`$；它可理解为模型平均面对多少个同等可能选择。（§4）
4. PPL 只在相同 tokenizer、数据、token 定义和条件口径下才可直接比。（§5）
5. 随机猜 $`m`$ 个等可能选项的准确率是 $`1/m`$；题越难不等于越贴近真实用途。（§6）
6. Arena 评的是某类用户在某类 prompt 上的成对偏好，不是“客观真理”。（§7）
7. Elo 分差决定预测胜率；拟合分数还有抽样误差、连通性和时间漂移。（§7）
8. LLM judge（用模型当裁判）便宜、可扩展，但可能偏爱长度、风格或迎合。（§8）
9. Agent benchmark 评的是 LM 加 scaffold、工具和环境；同一个 LM 换 scaffold 可变很多。（§9–§10）
10. ARC-AGI 尽量减少知识依赖，但仍不能证明“通用智能”或超人能力。（§11）
11. Safety 与国家、行业、上下文和使用者有关；单个拒答率不能代表全部风险。（§12）
12. Ecological validity 问“实验像不像真实使用”；越真实通常越难公开、复现和保护隐私。（§13）
13. Overlap 是训练测试内容相交；contamination 是不该进入训练的评测信息进入训练；memorization 是模型记住具体内容。三者相关但不等同。（§14）
14. 新日期不保证干净，公开 benchmark 也可能被复制到训练语料。（§14）
15. 评测前先说明目的：采购、测基础能力、测影响风险，还是给开发反馈。（§16）
16. 一张可信 evaluation card 至少报告样本、协议、成本、置信区间、污染检查和失败案例。（§17）

## 2. 从抽象的“好”到具体指标

### 2.1 Abstract construct 不是直接可测的东西

【课程内容，源码 33–44；视频 [02:01](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=121s)】讲者区分：

- **abstract construct（抽象构念）**：如“是好模型吗”“会推理吗”；
- **concrete metric（具体指标）**：如 MMLU accuracy、每百万 token 成本、人类胜率。

一把尺子能直接测桌长，却没有一把尺子能直接测“聪明”。我们只能选任务，让表现留下证据。因此：


```text
想知道的东西       设计的任务             得到的数字
医学帮助能力  ->  回答临床工作问题  ->  准确率/专家评分/风险率
代码维护能力  ->  修真实仓库 issue  ->  通过测试比例+成本+耗时
用户是否喜欢  ->  匿名比较两答案    ->  选择比例/Elo
```

箭头每走一步都会丢信息。选择题高分不等于能安全接诊；测试通过不等于代码可维护。

### 2.2 “好”至少有四条轴

【课程内容，源码 45–58】课件用四类图说明：

| 轴 | 人话问题 | 例子 | 不能推出什么 |
|---|---|---|---|
| capability | 能完成任务吗 | 综合 benchmark | 不推出便宜或受欢迎 |
| cost | 花多少钱、多久 | 每次运行成本 | 不推出答案正确 |
| preference | 用户更喜欢哪个回答 | Arena A/B | 不推出事实更真 |
| adoption | 人们实际用了多少 | OpenRouter 使用量 | 不推出模型更强 |

视频 [03:18](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=198s) 把 cost 单独提出；[04:11](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=251s) 又把 adoption 区分出来。

【补充解释】两个模型可以这样：

| 模型 | 准确率 | 每 1000 次成本 | 偏好胜率 | 使用次数 |
|---|---:|---:|---:|---:|
| A | 90% | ¥100 | 48% | 10 万 |
| B | 86% | ¥20 | 52% | 100 万 |

说“A 总体更好”会隐藏决策。做高风险科研可能偏 A；大规模低风险客服可能偏 B。

### 2.3 一个总分为什么危险

假设随意定义：


```math
\text{score}=0.7\times\text{accuracy}+0.3\times\text{preference}.
```

A 得 $`0.7\times90+0.3\times48=77.4`$；B 得 $`0.7\times86+0.3\times52=75.8`$。

若改成各 0.5，A 得 69，B 得 69。结论改变不是模型突然改变，而是人选择了权重。**权重是价值判断，不是自然常数。**

### 2.4 人群也属于评测定义

【视频补充，[04:43](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=283s)】使用量和偏好取决于谁能访问、价格、地区、产品入口和用户人群。大学生、医生和程序员可能偏好不同风格。

所以“80% 用户喜欢”至少要追问：

- 哪些用户？
- 看了哪些 prompt？
- 是盲测吗？
- 能选平局吗？
- 是否知道正确答案？
- 结果在哪个日期收集？

## 3. 概率、对数、平均数：PPL 前的四则运算桥

### 3.1 Probability 是 0 到 1 的数

**Probability（概率）** 表示事件发生的相信程度：0 是不可能，1 是确定。若公平硬币正面概率为 0.5，连续两次正面在独立假设下概率为


```math
0.5\times0.5=0.25.
```

语言模型在每一步给词表中每个 token 一个概率，所有候选概率相加为 1。

### 3.2 Token、tokenizer 与条件概率

**Token（词元）** 是模型处理的离散编号单位，可能是一个字、半个词或标点。**Tokenizer（分词器）** 是把文字变成 token IDs 的规则。不同 tokenizer 会把同一句话切成不同数量的 token。


```math
p(x_t\mid x_{<t})
```

读作：“已经看到第 $`t`$ 个 token 之前的所有 token 时，第 $`t`$ 个 token 的概率。”

- $`x_t`$：当前位置真实 token；
- $`x_{<t}`$：它之前的上下文；
- 竖线 $`\mid`$：在……条件下。

### 3.3 乘法：整条序列概率

自回归模型把每一步条件概率相乘：


```math
p(x_{1:T})=\prod_{t=1}^{T}p(x_t\mid x_{<t}).
```

$`T`$ 是 token 数；符号 $`\prod`$ 就是“从第 1 项乘到第 $`T`$ 项”。若两个真实 token 的概率是 0.5、0.25：


```math
p(x_{1:2})=0.5\times0.25=0.125.
```

### 3.4 $`e`$、自然对数和计算器

**$`e`$** 是约 (2.71828) 的常数。连续增长问题会自然出现它。本讲：

- $`\exp(a)=e^a`$；
- $`\ln(a)`$ 是自然对数，问“$`e`$ 的多少次方等于 $`a`$”；
- 两者互逆：$`\ln(e^a)=a`$，$`e^{\ln a}=a`$；
- $`\ln(ab)=\ln a+\ln b`$。

计算器例：输入 `ln(0.5)` 得约 (-0.6931)；输入 `exp(0.6931)` 得约 2。概率小于 1，所以它的自然对数为负数。

### 3.5 Log loss 与 NLL

**Log loss（对数损失）** 把真实答案的概率 $`p`$ 变成 $`-\ln p`$。**NLL（negative log-likelihood，负对数似然）** 是这些损失之和：


```math
\mathrm{NLL}=-\sum_{t=1}^{T}\ln p(x_t\mid x_{<t}).
```

概率越大，损失越小：

| 真实 token 概率 $`p`$ | $`-\ln p`$ |
|---:|---:|
| 1 | 0 |
| 0.5 | 0.6931 |
| 0.25 | 1.3863 |
| 0.1 | 2.3026 |

若两步概率 0.5 和 0.25：


```math
\mathrm{NLL}=0.6931+1.3863=2.0794.
```

### 3.6 Cross-entropy 是什么

**Cross-entropy（交叉熵）** 衡量真实分布 $`q`$ 下，模型分布 $`p`$ 给真实结果多少平均 log loss：


```math
H(q,p)=-\mathbb E_{x\sim q}[\ln p(x)].
```

$`\mathbb E`$ 意思是“按真实出现概率取平均”。若真实 A/B 各 0.5，模型给 A/B 为 0.8/0.2：


```math
H(q,p)=-[0.5\ln0.8+0.5\ln0.2]
=-[0.5(-0.2231)+0.5(-1.6094)]
=0.9163.
```

它不是 accuracy：模型可能每次 top-1 都选对，但给正确项 0.51 还是 0.99，会有不同 log loss。

### 3.7 Arithmetic mean 与 geometric mean

- **算术平均**：相加再除数量，如 $`(2+8)/2=5`$。
- **几何平均**：相乘后开 $`T`$ 次方，如 $`\sqrt{2\times8}=4`$。

概率连乘，因此 perplexity 最终对应概率倒数的几何平均，不是普通算术平均。

## 4. Perplexity：从序列概率逐步推出公式

### 4.1 定义和每个符号

【课程内容，源码 60–72；视频 [05:23](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=323s)】**Perplexity（困惑度，PPL）** 是平均 NLL 的指数：


```math
\boxed{
\mathrm{PPL}(x_{1:T})
=\exp\left(-\frac1T\sum_{t=1}^{T}\ln p(x_t\mid x_{<t})\right)
}
```

- $`T`$：被评分 token 数；
- $`p(x_t\mid x_{<t})`$：模型给真实 token 的概率；
- $`\ln`$：自然对数；
- 负号：把负的 log 概率变成非负损失；
- $`1/T`$：取每 token 平均；
- $`\exp`$：把 log 单位变回“有效选择数”。

### 4.2 从 NLL 推导成几何平均

利用 $`e^{a+b}=e^ae^b`$：


```math
\begin{aligned}
\mathrm{PPL}
&=\exp\left(-\frac1T\sum_t\ln p_t\right)\\
&=\exp\left(\frac1T\sum_t\ln\frac1{p_t}\right)\\
&=\left(\prod_t\frac1{p_t}\right)^{1/T}.
\end{aligned}
```

所以 PPL 是每一步“真实 token 概率倒数”的几何平均。

### 4.3 两个 token 的完整手算

仍用 $`p_1=0.5,p_2=0.25,T=2`$：

1. 序列概率：$`0.5\times0.25=0.125`$。
2. NLL：$`-\ln0.125=2.0794`$。
3. 平均 NLL：$`2.0794/2=1.0397`$。
4. PPL：$`e^{1.0397}\approx2.828`$。
5. 另一条路：$`\sqrt{(1/0.5)(1/0.25)}=\sqrt{2\times4}=\sqrt8\approx2.828`$。

两条路相同。若每一步真实 token 都恰有概率 $`1/4`$，PPL 就是 4。

### 4.4 “有效选择数”只是直觉

若 PPL=10，可以粗略想成模型每步像是在 10 个同等可能候选中犹豫。真实词表概率并不均匀，所以这是解释，不是说模型每步真的只看 10 个词。

### 4.5 Conditional perplexity

【课程内容，源码 84–92；视频 [12:44](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=764s)】聊天里通常只想评 response，不把 prompt 本身也计分：


```math
\mathrm{PPL}(y\mid x)
=\exp\left(-\frac1{|y|}\sum_{t=1}^{|y|}\ln p(y_t\mid x,y_{<t})\right).
```

$`x`$ 是 prompt，$`y`$ 是 response。例：prompt 有 100 token，回答只有 2 token，真实回答概率 0.5、0.25。条件 PPL 仍是 2.828，分母是回答长度 2，不是 102。

若把 prompt 也计入，模型可能靠“很会预测固定题目模板”掩盖回答很差。

### 4.6 为什么真实分布下 cross-entropy 最优

【课程内容；视频 [10:03](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=603s)】若真实分布是 $`q`$，模型报 $`p`$，cross-entropy（交叉熵）定义为：


```math
H(q,p)=-\sum_i q_i\ln p_i.
```

这里 $`i`$ 枚举所有可能结果，$`q_i`$ 是真实概率，$`p_i`$ 是模型报告的概率。真实分布自己的 entropy（熵）是：

```math
H(q)=-\sum_i q_i\ln q_i.
```

**KL divergence（Kullback–Leibler divergence，KL 散度）** 定义为：

```math
D_{\mathrm{KL}}(q\Vert p)=\sum_i q_i\ln\frac{q_i}{p_i}.
```

现在只做代数展开，不跳步：

```math
\begin{aligned}
D_{\mathrm{KL}}(q\Vert p)
&=\sum_i q_i(\ln q_i-\ln p_i)\\
&=\sum_i q_i\ln q_i-\sum_i q_i\ln p_i\\
&=-H(q)+H(q,p).
\end{aligned}
```

两边同时加 $`H(q)`$：

```math
\boxed{H(q,p)=H(q)+D_{\mathrm{KL}}(q\Vert p)}.
```

【补充解释】完整算二分类 $`q=[0.75,0.25]`$。计算器输入 $`\ln(0.75)`$ 得 $`-0.287682`$，输入 $`\ln(0.25)`$ 得 $`-1.386294`$：

```math
\begin{aligned}
H(q)
&=-[0.75\ln0.75+0.25\ln0.25]\\
&=-[0.75(-0.287682)+0.25(-1.386294)]\\
&=0.215762+0.346574\\
&=0.562336\approx0.5623.
\end{aligned}
```

**模型 A：$`p=q=[0.75,0.25]`$。** 每一项 $`q_i/p_i=1`$，而 $`\ln1=0`$，所以：

```math
D_{\mathrm{KL}}(q\Vert p)=0,
\qquad
H(q,p)=H(q)+0=0.5623.
```

**模型 B：$`p=[0.5,0.5]`$。** 先算 KL：

```math
\begin{aligned}
D_{\mathrm{KL}}(q\Vert p)
&=0.75\ln(0.75/0.5)+0.25\ln(0.25/0.5)\\
&=0.75\ln1.5+0.25\ln0.5\\
&=0.75(0.405465)+0.25(-0.693147)\\
&=0.304099-0.173287\\
&=0.130812\approx0.1308.
\end{aligned}
```

因此：

```math
H(q,p)=0.5623+0.1308=0.6931.
```

也可直接核对：

```math
-[0.75\ln0.5+0.25\ln0.5]=-\ln0.5=0.6931.
```

KL 非负要求 $`q,p`$ 是有效概率分布，而且所有 $`q_i>0`$ 的位置都有 $`p_i>0`$；若模型在真实可能事件上报 $`p_i=0`$，KL 会发散。KL 非负且只在 $`p=q`$（忽略 $`q_i=0`$ 的位置）时为 0，因此固定 $`q`$ 时 cross-entropy 在 $`p=q`$ 最小。这只说明 log loss 是 proper probability score（鼓励诚实概率），**不说明 PPL 足以测事实性、帮助性或安全性**。

## 5. Perplexity 能说明什么、不能说明什么

### 5.1 ID 与 OOD

**ID（in-distribution，分布内）** 指评测数据与训练目标分布近似；**OOD（out-of-distribution，分布外）** 指来源、领域、时期或格式改变。

【课程内容，源码 73–83】旧语言模型常在 Penn Treebank、WikiText-103、One Billion Word 等固定语料上比 PPL。视频 [07:52](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=472s) 转到 GPT-2：WebText 训练后，在多个未专门训练的数据集上做 zero-shot（零样例）评测。

【视频补充，[08:10](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=490s)】这常被描述为 OOD generalization（分布外泛化），但公开互联网数据边界不透明；不能排除内容重叠。

### 5.2 tokenizer 不同，PPL 通常不可直接比

句子“你好！”：

- tokenizer A 切 3 token，每 token 平均 NLL 1，PPL $`e^1=2.718`$；
- tokenizer B 切 1 token，NLL 2，PPL $`e^2=7.389`$。

不能据此说 A 的字符级预测一定更好，因为分母 token 数变了。至少要固定：

- tokenizer 和词表；
- 测试文本及预处理；
- 是否含 BOS/EOS 等特殊 token；
- 上下文长度、滑窗和条件范围；
- 按 token、byte 还是 character 归一化。

### 5.3 PPL 不等于 accuracy、事实性或帮助性

PPL 测的是“给真实文本多少概率”。它不直接测：

- 选择题是否选对；
- 生成事实是否真实；
- 是否遵守用户意图；
- 是否安全；
- 是否便宜和快速。

一个模型可以把常见错误说法预测得很顺，却仍然不真实。

### 5.4 LAMBADA 与 HellaSwag

【课程内容，源码 93–97】LAMBADA 是需要长上下文才能补最后一个词的 cloze（填空）任务；HellaSwag 是句子续写多选题。视频 [13:18](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=798s) 和 [14:41](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=881s) 展示它们如何把语言建模变成具体任务。

这说明条件概率能构造很多评测；不说明一个 PPL 数就覆盖所有能力。

### 5.5 为什么 PPL leaderboard 容易作弊

【课程内容，源码 98–106；视频 [15:39](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=939s)】若 leaderboard 让参赛者自己上报每个 token 的概率，平台很难确认这些数：

1. 真来自声明的模型；
2. 对整个词表正确归一化，总和为 1；
3. 没看过测试答案；
4. 没使用不同 tokenizer 偷换分母。

最幼稚的作弊是给每个真实答案上报概率 1，PPL 就是假 1。视频 [16:06](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=966s) 用这个极端例解释信任问题。

更可靠的做法是评测方运行模型、保留测试集、固定环境并记录完整 log probabilities。即使如此，也仍要检查污染。

### 5.6 课程结论的边界

视频 [09:46](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=586s) 把“PPL is all you need”称作一种信念，随后 [11:36](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=696s) 明确转向“PPL is more than you need”：真实产品常只关心条件回答或最终行为。

正确总结是：PPL 是概率建模的基础指标，但不是能力、产品质量或安全性的万能替身。

## 6. 考试型评测：MMLU、MMLU-Pro、GPQA 与 HLE

### 6.1 随机基线先算清

一题有 $`m`$ 个等可能选项，只随机选一个，答对概率是


```math
P(\text{correct})=\frac1m.
```

- 4 选 1：$`1/4=25\%`$；
- 10 选 1：$`1/10=10\%`$。

因此 40% 在四选题上高于随机 15 个百分点，在十选题上高于随机 30 个百分点。只报 40% 而不报选项数，会隐藏难度口径。

### 6.2 MMLU 测什么

【课程内容，源码 108–121；视频 [19:07](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=1147s)】**MMLU（Massive Multitask Language Understanding，大规模多任务语言理解）** 包含 57 个学科的选择题。名称写“理解”，但题目主要抽样知识和考试解题能力。

**Few-shot（少样例）** 是在正式问题前给少量示例。视频 [20:09](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=1209s) 展示 GPT-3 时代随规模提高的 few-shot 成绩。

构念偏差例：

- 想测“会做真实法律工作”；
- 实际测“能从四个短选项选法律知识答案”；
- 它漏掉访谈、检索、写作、审慎程度和责任判断。

所以 MMLU 是 proxy，不是整个职业能力。

### 6.3 饱和为什么会发生

**Saturation（饱和）** 指大量模型已接近高分，继续进步难以区分。若 100 题中 A=96、B=97，只差 1 题；换一批题可能倒序。

视频 [21:13](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=1273s) 提醒原 MMLU 对强模型逐渐不够难。饱和不等于能力已完美；可能只是尺子太短。

### 6.4 MMLU-Pro 做了哪些改变

【课程内容，源码 122–130；视频 [22:06](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=1326s)】MMLU-Pro：

- 清理较噪、过于简单的问题；
- 选项从 4 增到 10；
- 强调 **CoT（chain-of-thought，思维链）** 设置，即让系统生成中间推理再答；
- 课程引用论文观察：一些模型相对 MMLU 下降约 16–33 个百分点。

这些是特定评测和模型集合的观察，不是“加 6 个选项必降 16–33 点”的定律。

污染不只来自“测试题原文”。若一道题由某本教材或论文改写，而那份题源文档进入训练集，模型可能见过同一事实、同一推导甚至相近句子，却没有见过 benchmark 的最终题面。这种 **隐蔽 source overlap（题源重叠）** 比字符串查重难发现，所以考试报告还应追踪题目由哪些原始文档派生。

### 6.5 GPQA：专家和非专家的落差

【课程内容，源码 131–139；视频 [23:18](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=1398s)】**GPQA（Graduate-Level Google-Proof Q&A，研究生级、难以靠普通搜索回答的问答）** 由博士领域作者设计并验证。

图片流程是：作者写题 → 专家验证并修订 → 非专家尝试。**GPQA Diamond** 是筛得更严格的子集。课程快照中的人类/模型数字只说明当时该协议的难度；不能拿来给今天的模型排实时名次。

视频 [25:05](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=1505s) 提到专家约 65%，[25:25](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=1525s) 提到非专家可用搜索约 34%。两组人的招募、时间和规则不同，不能简化成“博士只有 65% 智力”。

### 6.6 HLE：把难度继续向上推

【课程内容，源码 140–148；视频 [27:25](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=1645s)】**HLE（Humanity's Last Exam）** 包含多学科、部分多模态问题。**Multimodal（多模态）** 表示输入不只有文字，也可能有图。

课件流程图给出的数量链是：

```math
\text{约 70,000 次出题尝试}
\to\text{约 13,000 个 submissions}
\to\text{约 6,000 个 expert-reviewed candidates}
\to\text{2,500 个 public questions}.
```

每一步都会改变题目分布。图中写 public/private split，但**没有给出 private 集的具体题数**，所以笔记不补猜。保留私有部分能降低直接针对测试题调参的风险，不保证永不泄漏。

### 6.7 “更难”不等于“更有用”

视频 [29:33](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=1773s) 指出，多选题可以被设计得任意难。你可以问极冷门事实，但用户根本不需要它。

判断考试型 benchmark 至少分四问：

1. **Difficulty（难度）**：目标系统做对有多难。
2. **Discriminative power（区分力）**：不同系统的成绩是否能被这把尺子拉开。
3. **Validity（效度）**：它是否测到声称的构念。
4. **Realism（现实性）**：任务和真实使用是否接近。

难度与区分力不是同一个数：

- 所有模型都得 0%：任务可能极难，但模型全挤在一起，区分力低；
- 模型在 40%–70% 展开：未必更难，却可能更能区分当前模型；
- 所有模型都得 99%：通常已饱和，区分力也低。

一个 benchmark 可以很难、可重复，却区分力低或不现实。

### 6.8 Accuracy 的抽样不确定性

【补充】若 $`n`$ 道近似独立的二值题，正确率 $`\hat p=c/n`$，标准误可粗估为


```math
SE\approx\sqrt{\frac{\hat p(1-\hat p)}n}.
```

100 题答对 80：


```math
SE=\sqrt{0.8\times0.2/100}=\sqrt{0.0016}=0.04.
```

粗略 95% 区间用 $`\hat p\pm1.96SE`$：


```math
0.8\pm1.96\times0.04=0.8\pm0.0784,
```

约 $`[0.722,0.878]`$。**Confidence interval（置信区间）** 是重复抽样程序的覆盖性质，不是说“这一次区间有 95% 概率包含固定真值”；小样本或相关题目还应使用更合适方法。

**Calibration（校准）** 问概率是否与长期频率相符。例如把模型所有“80% confidence”的题收成一组，若长期约 100 题中答对 80 题，这一组较校准；若只对 45 题，虽然某些 top-1 仍可能正确，80% 这个信心数却过高。

### 6.9 从模型文本到 accuracy：中间还有 extractor

选择题模型先输出 text，再由 **extractor/parser（抽取器/解析器）** 变成标准 label，最后做 **exact match（完全匹配：规范化后的预测标签必须与标准标签相同）**：

    模型文本 -> extractor/parser -> 标准 label -> 与参考 label 完全比较

参考 label 是 B：

| 模型文本 | 简单 parser 可能得到 | 结果 |
|---|---|---|
| B | B | 正确 |
| 答案是 B，因为…… | 若只接受单字符，可能 parser fail | 可能误判 |
| b | 若不统一大小写，得到 b | 可能误判 |
| 第二项 | 若标签顺序 A/B/C/D，需映射到 B | 取决于协议 |
| B、C 都可能 | parser 需规定多标签怎么办 | 取决于协议 |

**Parser fail（解析失败）** 是系统输出存在，但评分程序无法映射到合法标签；它不等于模型完全没有知识。

以下都属于 evaluation protocol（评测协议），必须预先固定并报告：

- direct answer（只答标签）还是 CoT；
- 用哪个 regex（regular expression，正则表达式）抽答案；
- 大小写、标点、标签顺序如何归一化；
- 多次 sampling 后 majority vote（多数投票）如何计；
- 每题 reasoning token、时间和工具预算。

这就是为什么同一个模型、同一题库也可能因 harness（评测执行程序）不同而得到不同 accuracy。

## 7. Chatbot Arena：从 A/B 选择到 Elo

### 7.1 为什么开放问答不能只做 exact match

问题“甜菜怎么做？”可能有许多都不错的答案：烤、煮、做沙拉。前文的 exact match 若直接要求开放回答字符等于唯一参考答案，会错杀合理回答。

【课程内容，源码 155–174；视频 [32:58](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=1978s)】Arena 的办法：

1. 收真实用户 prompt；
2. 随机抽两个匿名模型；
3. 并排展示回答；
4. 用户选左胜、右胜、平局或都差；
5. 多场比较拟合相对分数。

匿名能减少品牌偏见，但不能消除答案长度、排版和语气偏见。

### 7.2 Pairwise preference 不是事实裁判

**Pairwise preference（成对偏好）** 问“两个中更喜欢哪个”。视频 [36:29](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=2189s) 强调它把很多东西混在一起：正确、详细、礼貌、有趣、迎合。

若用户不知道事实答案，他可能偏爱自信但错误的长回答。**Sycophancy（迎合）** 是模型顺着用户观点而非诚实纠正；视频 [37:25](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=2245s) 把它列为偏好评测风险。

### 7.3 Elo 胜率公式逐项解释

【课程内容，源码 175–183】Elo 在这里是从成对胜负拟合的相对 rating。对模型 A、B：


```math
P(A\text{ beats }B)=\frac{1}{1+10^{(R_B-R_A)/400}}.
```

- $`R_A,R_B`$：A、B 的 rating；只有差值有意义；
- 400：传统 Elo 的尺度常数；
- 分差为 0 时，胜率是 (1/(1+1)=0.5)。

例：$`R_A=1200,R_B=1000`$：


```math
\begin{aligned}
(R_B-R_A)/400&=(1000-1200)/400=-0.5,\\
10^{-0.5}&=1/\sqrt{10}\approx0.3162,\\
P(A\text{胜})&=1/(1+0.3162)\approx0.7597.
\end{aligned}
```

即模型假设下约 76%，不是保证 100 场一定赢 76 场。

Elo 只看差值，所以整体平移不改变预测。原 ratings：

```math
(R_A,R_B)=(1200,1000),\qquad R_A-R_B=200.
```

两者都加 1000：

```math
(R_A',R_B')=(2200,2000),\qquad R_A'-R_B'=200.
```

两次代入的指数都为 $`-200/400=-0.5`$，胜率都为 $`75.97\%`$。因此 “2200 比 1200 绝对强 1000 分”没有意义；必须看同一拟合中的相对差。

### 7.4 分数怎样从很多比赛拟合

**Likelihood（似然）** 是在给定 rating 时观察到现有胜负数据的概率。拟合选择让全部比赛结果联合 likelihood 最大的 ratings。

最小例：A 对 B 打 10 场，A 赢 7。若暂忽略平局，经验胜率 0.7。反推分差：


```math
\Delta R=400\log_{10}\frac{0.7}{0.3}
\approx400\times0.368=147.2.
```

计算器操作：先输入 $`0.7/0.3=2.3333`$，再按 $`\log`$ 或 $`\log_{10}`$ 键，得到约 $`0.368`$，最后乘 400。这里是**常用对数**，底数为 10；不是自然对数 $`\ln`$。

所以 A 比 B 约高 147 分。10 场很少，分差非常不稳定；1000 场会更稳。

#### 平局怎样处理会改变结果

假设 A/B 共 100 场：A 赢 45、B 赢 35、tie 20。

**协议一：每个 tie 各算半胜。**

```math
\text{A score}=(45+20/2)/100=55/100=55\%.
```

**协议二：直接丢掉 tie。**

```math
\text{A win rate}=45/(45+35)=45/80=56.25\%.
```

同一批比赛只因预处理不同就差 $`1.25`$ 个百分点。还可以使用专门的 tie model（平局模型），为“平局概率”另设参数；这又不是前两种简单计法。真实 leaderboard 必须披露：

- tie/“两者都差”如何编码；
- 是否过滤异常用户或 prompt；
- 用 Bradley–Terry、Elo、带 tie 模型还是别的拟合；
- rating 基准如何固定；
- 模型版本和数据截止日期。

#### Rating 的置信区间不能套独立 accuracy 的 SE

Arena 里一个用户可能投很多票，同一 conversation 里的判断也相关。**Cluster（簇）** 是一组可能相关的观察，例如同一用户或同一对话。**Bootstrap（自助重采样）** 是从已有样本中有放回抽取，重复构造许多“仿真数据集”。

较稳妥的 rating 区间流程：

1. 选 cluster 单位，如 user 或 conversation；
2. 有放回抽取同样数量的 clusters；
3. 每次都从头重新拟合所有模型 ratings；
4. 重复很多次；
5. 对某模型的 bootstrap ratings 取 2.5% 和 97.5% 分位数。

这保留了簇内相关性，也把“整个 rating 是联合拟合出来的”算进去。不能把 rating 当成 80/100 accuracy，直接套 $`\sqrt{\hat p(1-\hat p)/n}`$。

### 7.5 比较图必须连通

若 A 只和 B 比，C 只和 D 比，两个小组之间没有比赛，就无法确定 A 与 C 谁高。**Connected comparison graph（连通比较图）** 把模型看成节点、比赛看成边；只有能沿边连接，才能把 ratings 放到共同尺度。

视频 [37:42](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=2262s) 把稀疏但连通的比较看作 Arena 的优点；[38:10](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=2290s) 也提醒排行榜随数据和模型变化。

### 7.6 Arena 的五类偏差

1. **Population bias（人群偏差）**：来网站的用户不代表所有部署用户。
2. **Selection bias（选择偏差）**：被提交和被投票的 prompt 不是随机全体。
3. **Style bias（风格偏差）**：长、分点、热情可能被偏爱。
4. **Knowledge asymmetry（知识不对称）**：投票者不知道事实答案。
5. **Temporal drift（时间漂移）**：模型版本、用户和提示随时间改变。

因此报告应带日期、样本量、置信区间、类别分层和 tie 规则。

## 8. AlpacaEval、WildBench 与 LLM judge

### 8.1 LLM judge 是什么

**LLM judge（语言模型裁判）** 是让另一个语言模型按规则给候选回答打分或做成对选择。优点是便宜、快、规模大；风险是裁判也有偏差、知识错误和提示敏感性。

“与人类分数相关”不等于“有效”：两个指标可能都偏爱长度，所以相关很高，却都没更好地测事实性。

### 8.2 AlpacaEval 的长度问题

【课程内容，源码 184–193；视频 [38:21](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=2301s)】AlpacaEval 用固定指令集，让裁判比较候选回答与参考系统回答。**Win rate（胜率）** 是候选被选中的比例。

课程强调的漏洞：较长答案往往更易获胜。模型可以增加不必要细节来刷分。AlpacaEval 2.0 报告 **length-controlled win rate（长度控制胜率）**，用统计回归尽量扣除长度关系。

【补充解释】假设原始 100 场：

- 短答案模型赢 45 场，平均 100 字；
- 长答案模型赢 60 场，平均 500 字。

不能直接把多出的 15 场全当能力；长度与题型、质量可能一起变化。回归控制只能降低已建模的偏差，不能证明所有混杂都消失。

### 8.3 WildBench：先生成检查表再裁判

【课程内容，源码 194–206；视频 [41:39](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=2499s)】WildBench 从真实聊天中抽样任务，先为每个 prompt 生成 checklist（检查项），再让 judge 依检查项打分或成对比较。

例：用户要求“给三个建议，每个不超过 20 字，并指出风险”。检查表可拆成：

1. 恰好三个建议；
2. 每项不超过 20 字；
3. 每项含风险；
4. 内容与问题相关。

比一句“整体好不好”更可审计。

### 8.4 Pairwise 为什么常比绝对分更稳定

绝对打 1–10 分时，不同裁判对“7 分”的含义不同。成对比较只问 A/B，认知负担较小。但它仍会受顺序、长度、风格和裁判身份影响。

一个简单检查：同一对答案交换左右位置再评。若第一次 A 胜、交换后原来的 A 却输，说明有 position bias（位置偏差）。

### 8.5 Rubric 和 reliability

**Rubric（评分量规）** 是明确列出的判分标准。**Reliability（信度）** 问重复评或换相似裁判时结果稳不稳。**Validity（效度）** 问分数是否真的代表目标。

高信度不保证测量就好。一把永远多量 5 厘米的尺子，每次量同一物体都得到几乎相同结果，所以它的 **reliability（信度）高**；但它有固定的 **systematic bias（系统性偏差）**，绝对长度不准确。这个例子本身只证明“稳定但有偏”，不能单凭它断言 criterion validity 高低，因为我们还没有指定要预测的外部效标。

**Criterion validity（效标效度）** 问：这个分数能否对应或预测一个外部目标。例：一套极冷门 trivia（冷知识）考试每次重测都很稳定，却不能预测客服是否能正确处理退货；它相对“真实客服成功”这个外部效标的效标效度就低。

### 8.6 一个 judge 评测的最小审计

- 明确 judge 模型、版本、prompt 和 decoding；
- 随机左右顺序；
- 允许 tie；
- 抽样让领域人类复核；
- 分别报告正确性、风格、遵循指令；
- 检查长度和自家模型偏好；
- 给 disagreement（分歧）案例，不只给相关系数。

这里的 **$`R^2`$（决定系数）** 粗略问“拟合关系解释了结果变化的多大比例”。高 $`R^2`$ 只说明平均关系贴得好，不保证概率校准、不保证每个群体都好，也不证明指标真的测到了目标构念。

## 9. Agentic evaluation：评的是“模型加脚手架”

### 9.1 Agent 从零定义

【课程内容，源码 208–215；视频 [44:58](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=2698s)】**Agent（智能体）** 是语言模型加上 scaffold（脚手架）后，在环境中反复观察、计划、行动、再观察的系统。

**Scaffold（脚手架）** 包括：system prompt、工具调用、记忆、待办清单、重试、上下文压缩、子任务分派等。


```text
任务 -> 模型提出行动 -> 工具/环境执行 -> 返回观察
  ^                                      |
  |------------ 更新记忆后继续 ----------|
```

视频 [45:34](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=2734s) 明确：agentic benchmark 不是只测一个裸 LM。

### 9.2 同一个模型为何会有不同分数

系统 A 每次失败就停止；系统 B 会读测试错误、修改代码、重试 3 次。即使底层 LM 相同，B 更可能通过。因此 leaderboard 行应写“model + scaffold + tools + budget”，不能只写 model 名。

### 9.3 Budget 也是规则

**Budget（预算）** 可包括：

- 最多生成 token 数；
- 最多工具调用次数；
- 最长墙钟时间；
- 并发任务数；
- API/计算费用；
- 是否可访问网络。

给一个 agent 10 次尝试、另一个 1 次，再比较 pass rate，不公平。

### 9.4 pass@k 的两种口径

【补充】先分清两个不同实验。

**实验 A：真正独立地重新生成。** 若每次尝试都独立、每次成功率都是同一个 $`p`$，最多试 $`k`$ 次，至少一次成功概率为


```math
1-(1-p)^k.
```

若 $`p=0.2,k=3`$：失败三次概率 $`0.8^3=0.512`$，至少成功一次为 $`1-0.512=0.488`$。

**实验 B：先生成 $`n`$ 份，再估计 pass@k。** 契约是：

1. 这 $`n`$ 份来自同一 model、同一 prompt、同一 temperature 和同一预算；
2. 采样可视为 **exchangeable（可交换）**：只交换样本编号，不应改变联合分布；
3. 其中有 $`c`$ 份通过评分器，且 $`0\le c\le n`$；
4. $`k\le n`$；
5. 公式想象的是：从**已经生成好的** $`n`$ 份里，无放回、均匀地选一个大小为 $`k`$ 的子集。这是统计上的“选子集”，不是说语言模型生成时无放回。

总共有 $`\binom nk`$ 个大小为 $`k`$ 的子集。全失败样本有 $`n-c`$ 份，所以“选中的 $`k`$ 份全失败”的子集数是 $`\binom{n-c}{k}`$。因此


```math
\mathrm{pass@}k=1-\frac{\binom{n-c}{k}}{\binom nk}.
```

$`n=10,c=2,k=3`$：失败样本数 $`n-c=8`$，$`\binom{8}{3}=56,\binom{10}{3}=120`$，所以 $`1-56/120=0.5333`$。若 $`n-c<k`$，失败样本根本凑不出 $`k`$ 个，分子按 0 计，pass@k 就是 1。

不能直接套公式的情况：看过前一次答案后才决定如何重试、不同样本使用不同 token/工具预算、混用不同 model 或 temperature、样本高度相关且不满足可交换假设。两种公式假设不同，报告时必须写清生成协议与选样规则。

### 9.5 工具版本也会改变结果

编译器、依赖、搜索 API、网页内容、硬件和时间限制都会变化。可信报告要保存容器、依赖锁、数据版本和运行日志。

## 10. SWE-bench、Terminal-Bench、CyBench 与 MLE-bench

### 10.1 SWE-bench：修真实仓库 issue

【课程内容，源码 216–222；视频 [45:56](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=2756s)】**SWE-bench（Software Engineering Benchmark）** 给 agent 一个代码仓库和 issue（问题报告），要求生成 patch（代码补丁），再跑测试判断。

最小数据流：

```text
仓库 + issue -> agent 修改文件 -> patch -> 单元测试 -> pass/fail
```

**Unit test（单元测试）** 是自动检查某段软件行为的程序。测试通过很有用，但只证明已覆盖断言通过；没覆盖的安全性、可读性和性能仍可能坏。

### 10.2 Terminal-Bench：在容器终端中完成任务

【课程内容，源码 223–230；视频 [47:53](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=2873s)】**Terminal-Bench**把 agent 放进 container（隔离运行环境），给自然语言任务和终端工具，再用隐藏测试评分。

**Hidden tests（隐藏测试）** 不提前给参赛者看，减少针对公开测试硬编码。仍要固定：容器镜像、CPU/GPU、网络、超时、工具版本和重试预算。

课程中的任务数、榜单和人类耗时是当时版本快照；版本更新后可能不同。

### 10.3 CyBench：网络安全双用途评测

【课程内容，源码 231–238；视频 [49:17](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=2957s)】**CyBench**基于 CTF（Capture the Flag，夺旗赛）式任务：agent 在隔离环境行动，找到用于证明完成的 flag。

笔记只保留安全层级：任务、观察、动作、环境、评分和耗时；不提供绕过系统的可操作步骤。网络安全评测有 **dual use（双用途）**：同一能力可帮助防御，也可能被滥用。

### 10.4 MLE-bench：完整机器学习工程

【课程内容，源码 239–243；视频 [50:59](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=3059s)】**MLE-bench（Machine Learning Engineering Benchmark）** 把竞赛式数据、说明和计算环境交给 agent，最终用 submission 文件评分。

它评的不只是“知道算法”，还包括：读数据、调试、训练、管理时间、生成正确格式文件。

### 10.5 为什么 agent benchmark 要看 trace

**Trace（轨迹）** 是 agent 每一步观察、思考摘要、工具调用和结果的记录。只看最终 pass/fail 看不到：

- 是否误打误撞；
- 是否利用测试漏洞；
- 是否做了危险操作；
- 在哪一步浪费预算；
- 失败来自 LM 还是 scaffold。

视频 [51:45](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=3105s) 到 [53:08](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=3188s) 逐项讲计划、待办、委派和 context engineering（上下文工程）。

### 10.6 一个公平 agent 结果表应至少有

| 项 | 为什么 |
|---|---|
| 底层模型和版本 | LM 本身会变 |
| scaffold 版本 | 循环和提示会变 |
| 每题最大 token/时间/费用 | 更多预算通常提高成功率 |
| 工具与网络权限 | 能力边界不同 |
| 并发数 | 影响吞吐和超时 |
| pass@1 与 pass@k | 区分一次和多次机会 |
| 平均成本、尾部耗时 | 成功但极贵也重要 |
| 完整 trace 抽查 | 发现测试投机和危险路径 |

## 11. ARC-AGI：尽量隔离知识的“纯推理”评测

### 11.1 Fluid intelligence 是什么

【课程内容，源码 257–284；视频 [53:56](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=3236s)】**Fluid intelligence（流体智力）** 粗略指不依赖已背知识、面对新问题发现规律的能力。ARC-AGI 用彩色网格转换任务，给几个输入/输出例子，让系统推断新网格的规则。

例：训练例都把红格右移一格，测试输入有红格在第 2 列；合理输出在第 3 列。这比问“法国首都是哪”更少依赖事实知识。

### 11.2 ARC-AGI 1、2、3 的课程脉络

- **ARC-AGI-1**：静态网格转换；课程称 2019 年提出。
- **ARC-AGI-2**：更强调多步组合；视频 [55:36](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=3336s) 进入第二版。
- **ARC-AGI-3**：课程 2026 快照展示互动环境，agent 通过行动发现规则；视频 [57:32](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=3452s)。

本地图中的分数和模型名称只用于看历史趋势。ARC-AGI-3 图上的极低分是早期快照，不能作为当前榜单。

### 11.3 “知识隔离”并不完全

视频 [58:05](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=3485s) 主动提出 caveat（限制）：

- 模型需要会理解说明、图像和接口；
- 搜索、程序合成和视觉先验仍是知识；
- 题目选择本身定义了哪类推理重要；
- 人类可解不等于测到全部人类智力；
- 高分不等于现实任务中的可靠规划。

### 11.4 难题集的选择效应

若只保留“现有模型做不出的题”，新 benchmark 会很难，但它不代表全部真实工作。**Selection effect（选择效应）** 是筛选规则改变样本分布。

正确表述：ARC-AGI 为少知识依赖的抽象任务提供一把有用尺子；它不是“通用智能证书”。

## 12. Safety evaluation：安全不是一个拒答率

### 12.1 Safety 的构念依赖上下文

【课程内容，源码 286–312；视频 [60:12](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=3612s)】**Safety evaluation（安全评测）** 问系统在可能造成伤害的情境中怎样表现。

同一句内容，在教育、防御、医疗、犯罪等上下文里风险可能不同；法律和社会规范也随国家变化。视频 [63:30](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=3810s) 明确强调 contextual（情境相关）。

### 12.2 HarmBench 与 AIR-Bench

- **HarmBench**：课程讲义列出一组标准化有害行为，用于测拒绝和安全响应。
- **AIR-Bench**：按多类风险、政策和情境组织更广的安全评测。

这些 benchmark 的类别数和 prompt 数是具体版本快照。安全分数必须带政策、judge、攻击强度和正常请求误拒率。

### 12.3 False negative 与 false positive

- **False negative（漏拦）**：危险请求被错误放行。
- **False positive（误拦）**：安全请求被错误拒绝。

100 个危险请求漏 5 个，漏拦率 $`5/100=5\%`$。100 个正常请求错拒 20 个，误拦率 20%。只压低漏拦可能让模型什么都不回答，所以要一起报。

### 12.4 Jailbreak 与 GCG 的安全边界

**Jailbreak（越狱提示）** 是试图绕过模型安全约束的输入。课程提到 **GCG（Greedy Coordinate Gradient）** 可自动搜索攻击性提示并发生迁移；视频 [62:28](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=3748s)。

本笔记只讲评测思想：

1. 在隔离、授权环境生成测试；
2. 只保存必要的受控样本；
3. 测成功率、误拒率和迁移边界；
4. 报告修复前后结果；
5. 不提供可直接复现伤害的攻击字符串或步骤。

### 12.5 Safety 不只防恶意用户

视频 [63:55](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=3835s) 后列出更广风险：hallucination（幻觉，即无依据却像真的输出）、sycophancy、错误医疗建议、不平等影响、过度依赖和批判性思维下降。

因此“拒绝所有明显恶意问题”只覆盖安全的一小部分。

### 12.6 双用途评测的报告原则

- 公开总体指标和防护结论；
- 限制会直接提高攻击能力的细节；
- 让合格的独立研究者复核；
- 同时报 capability 与 misuse risk；
- 区分模型能否做、用户是否会做、系统是否允许做。

## 13. Realism 与 ecological validity：像不像真实世界

### 13.1 Ecological validity

【课程内容，源码 314–337；视频 [65:23](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=3923s)】**Ecological validity（生态效度）** 问实验环境、任务和参与者是否接近模型真正被使用的环境。

四选题容易评分但不像多数工作；真实工作文件、工具和多轮修改更像部署，却更贵、更隐私敏感、更难重复。

### 13.2 GDPVal

【课程内容；视频 [66:00](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=3960s)】GDPVal 尝试用专业人员交付物评估经济工作任务。课程快照提到覆盖美国 GDP 较大的 9 个行业、44 个职业，经验人员平均约 14 年。

本地图展示制造工程、金融分析、护理、视频编辑、客服等不同 deliverable（交付物）。这比统一短答案更现实，也让评分、保密和工具环境更复杂。

### 13.3 MedHELM

【课程内容；视频 [66:37](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=3997s)】MedHELM 强调从旧式医学考试转向临床任务。课程快照为 121 个任务、29 名临床专家参与设计或审查。

医学准确率不是唯一目标，还需看：校准、伤害、遗漏、不同患者群体、公平性、临床工作流和隐私。笔记不把 benchmark 分数当医疗部署许可。

### 13.4 Clio：从真实使用聚合任务类别

【课程内容；视频 [67:34](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=4054s)】Clio 用模型辅助对真实对话做隐私保护的聚合分析。课程图片比较人工 ground truth 类别数量与自动分类的 true positive/false positive。

**Ground truth（参考真值）** 是评测采用的人工或权威标签；它也可能有错误。**True positive（真正例）** 是正确识别的目标项；false positive 是误报。

### 13.5 现实性—隐私—可复现三角

| 做法 | 现实性 | 隐私 | 可复现 |
|---|---|---|---|
| 公开合成选择题 | 较低 | 高 | 高 |
| 脱敏真实样本 | 中高 | 中 | 中 |
| 私有真实工作流 | 高 | 需严格保护 | 低 |

视频 [68:20](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=4100s) 提醒这个取舍。没有方案同时免费得到三者最大值。

## 14. Validity、污染、重叠与记忆

### 14.1 六个容易混的质量词

【补充解释】

- **Construct validity（构念效度）**：指标是否覆盖声称的抽象能力。
- **Criterion validity（效标效度）**：分数是否与外部重要结果一致，如真实工作成功率。
- **Reliability（信度）**：重复测量是否稳定。
- **Difficulty（难度）**：任务总体有多难，例如多数系统接近 0%。
- **Discriminative power（区分力）**：分数能否把被比较系统拉开。所有系统都 0% 可以非常难，却几乎没有区分力；许多系统落在 40%–70% 时反而可能更好区分。
- **Ecological validity（生态效度）**：任务是否像真实使用。

例：一套 1000 道极冷门 trivia 每次测都很稳定，信度高、难度高；却未必有效测客服工作，构念和生态效度低。

### 14.2 overlap、contamination、memorization

【课程内容，源码 338–346；视频 [68:55](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=4135s)】

- **Train-test overlap（训练—测试重叠）**：训练数据和测试数据有相同或近似内容。
- **Contamination（污染）**：本应保持独立的评测内容或答案进入训练/调参流程，破坏公平解释。
- **Memorization（记忆）**：模型能复现某个训练实例或其特征。

重叠不必然证明记忆；记忆也可能来自别的重复来源；污染强调评测设计被泄漏。三者不能互换。

### 14.3 Exchangeability 检测直觉

【课程内容，源码 347–350；视频 [69:46](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=4186s)】**Exchangeability（可交换性）** 粗略指：若样本来自同一机制，改变无关的排列顺序，不应系统性改变联合概率规律。

课程图示：benchmark 的 canonical order（官方顺序）与 shuffled order（打乱顺序）相比，模型对后续问题的 log probability 若异常依赖官方次序，可能曾见过整段顺序。

但这是线索，不是铁证。顺序本身也可能带主题结构；模型分词、上下文长度和随机噪声都可影响结果。

### 14.4 四条减轻污染路线

【课程内容，源码 347–361】

1. **推断**：用顺序、措辞或似然异常找重叠信号；依赖假设。
2. **报告**：模型提供者披露训练—测试 overlap，并给不确定性；依赖诚实和数据治理。
3. **新鲜评测**：模型训练截止后收集新题；公开后仍可能进入下轮训练。
4. **私有评测**：隐藏题目，由可信方运行；可审计性和开放复现较弱。

视频 [71:54](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=4314s) 提醒 timestamps（时间戳）也不保证安全：网页可能被改日期、复制或提前泄露。

### 14.5 什么是“检测到记忆”的更强证据

证据强度从弱到强：

1. 该题公开很久；
2. 模型答得异常好；
3. 改写后成绩大跌；
4. 能逐字补出罕见错误和顺序；
5. 训练日志或检索证明确实包含该实例。

前两项只是怀疑，不能单独宣布“模型作弊”。

<a id="s15"></a>
## 15. 数据集和测试本身也会坏

### 15.1 Gold label 也可能错

**Gold label（标准标签）** 是数据集认定的答案，不代表绝对真理。题目歧义、版本变化、标注者错误都可能让正确模型被判错。

抽样审计例：从 1000 题随机查 100 题，发现 8 题标签或题干有问题，样本问题率 $`8/100=8\%`$。这不能断言全体正好 8%，但足以提醒榜单分差 1% 可能没意义。

### 15.2 SWE-bench Verified 与 Platinum

【课程内容，源码 362–366；视频 [73:19](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=4399s)】SWE-bench Verified 通过人工审查提高任务可解性和测试质量。课程又提到为 benchmark 建更严格的 Platinum 版本。

“Verified/Platinum”不是神奇印章；仍要说明谁审、审什么、漏了什么和版本日期。

### 15.3 Unit test 漏洞

假设需求是“排序并不得修改原数组”，测试只检查输出是否排序。系统原地修改输入，也会通过。测试覆盖了结果，没覆盖副作用。

Agent 还可能：

- 删除失败测试；
- 硬编码公开样例；
- 返回空结果触发错误的默认成功；
- 修改评分脚本；
- 利用超时或环境 bug。

这类行为说明 benchmark 评到了“钻规则”，不是目标软件能力。

### 15.4 Docent 与 trace audit

【课程内容，源码 367–369；视频 [75:07](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=4507s)】Docent 代表一种方向：用模型辅助检查 agent trace，发现异常策略、测试漏洞和失败模式。

LLM 审计器也可能漏检或误报，所以应该：规则检查 + 人类抽查 + 多样案例 + 可追溯证据，而不是再加一个模型就宣布问题解决。

## 16. 到底为何而评：四个目的、三个对象

### 16.1 四个目的

【课程内容，源码 371–392；视频 [75:41](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=4541s)】评测目的至少四类：

1. **采购/使用决策**：这个系统适合我的任务、预算和风险吗？
2. **测基础能力**：模型在受控任务上能做什么？
3. **测收益与伤害**：部署对人、组织和社会有什么影响？
4. **开发反馈**：哪个训练或系统改动值得保留？

同一个数字不一定服务四者。开发者要低噪声的快速指标；采购者更关心自己工作流、成本、隐私和故障。

### 16.2 三个被评对象

| 对象 | 固定什么 | 改变什么 | 例子 |
|---|---|---|---|
| method | 数据、模型预算、目标 | 训练算法 | nanoGPT speedrun |
| model | 提示/工具尽量固定 | 权重版本 | PPL、MMLU |
| agent/system | 完整部署协议 | 模型+scaffold组合 | SWE-bench |

视频 [76:47](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=4607s) 对比早期更常评 method，今天常评模型或系统。

### 16.3 nanoGPT speedrun 为什么是方法评测

【课程内容；视频 [77:04](https://www.youtube.com/watch?v=JpAxdTWQJxM&t=4624s)】固定模型家族、数据和目标 validation loss（验证损失），比较到达目标所需时间或 token。

**Validation loss** 是在不用于参数更新的验证集上算的 loss。它让新 optimizer、kernel 或 recipe 在共同终点竞争。

但规则选择仍会偏向某些方法：固定 124M 模型、某个硬件和某个 loss，不代表在 70B 或别的数据上仍排序相同。

### 16.4 Evaluation 是规则的游戏

任何 benchmark 都规定：输入、工具、时间、输出格式、评分器。系统会优化这些规则。**Goodhart's law** 的直觉是：当一个指标变成强目标，参与者会找到提高指标但不提高原构念的办法。

所以不是“禁止优化 benchmark”，而是让作弊路径代价高、持续刷新任务、报告多维证据、检查失败案例。

## 17. 一套可执行的 evaluation card 与 anti-gaming 流程

### 17.1 先写 evaluation card

**Evaluation card（评测卡）** 是运行前写下的评测契约：

1. 决策：这份结果要支持什么决定？
2. 构念：真正想测什么，明确不测什么？
3. 人群与情境：谁在什么场景用？
4. 数据：来源、日期、语言、许可、去重和隐私。
5. 协议：prompt、few-shot、工具、预算、temperature、重试。
6. 指标：主指标、次指标、成本和风险。
7. 不确定性：样本量、置信区间、重复运行。
8. 污染：训练截止、重叠检查、私有 holdout。
9. 失败：分层错误、最坏案例、人工审计。
10. 版本：代码、模型、依赖、硬件和时间。

**Temperature（温度）** 是调节采样随机性的参数；temperature=0 常近似使用最高概率输出，但具体 API 行为要查实现。

### 17.2 一个客服评测的 worked example

目标：“低风险退货客服是否可部署。”

- 500 条经许可、脱敏的真实请求；
- 类别：普通退货 300、政策边界 100、欺诈风险 50、情绪升级 50；
- 主要指标：政策正确率；
- 次指标：解决率、人工偏好、平均成本、P95 延迟；
- **P95 latency（95 分位延迟）**：95% 请求耗时不超过的值；
- 安全门槛：欺诈风险漏报率低于预设阈值；
- 每个系统相同工具、最多 2 次调用、相同知识库快照；
- 50 条双人复核，分歧由第三人裁决；
- 单独报告四类，不只报总平均。

若 300 条普通退货对 285，准确率 $`285/300=95\%`$；50 条风险漏 4，漏报率 $`4/50=8\%`$。总准确率可能很好，但安全门槛仍不通过。

### 17.3 Anti-gaming checklist

**Anti-gaming（防刷指标）** 不等于不让系统发挥，而是检查“高分路径是否偏离目标”：

- 隐藏一部分测试；
- 每轮加入新题并保留版本；
- 扰动表面格式和选项顺序；
- 检查长度、拒答和输出模板；
- 限制并记录预算；
- 沙箱隔离评分器与答案；
- 检查是否修改测试；
- 用独立人类审计最强、最弱和异常案例；
- 预注册主指标，避免看结果后换指标；
- 把 benchmark 分数和真实 pilot（小规模试点）关联验证。

### 17.4 Decision tree

```text
你要做什么决定？
├─ 选产品 -> 真实用户任务 + 成本/延迟/风险 + 小规模试点
├─ 比基础模型 -> 固定prompt/工具/预算 + 多能力集 + 污染审计
├─ 比训练方法 -> 固定模型/数据/硬件/终点 + 多seed + 资源账
└─ 评agent -> 固定scaffold或把scaffold明确作为系统一部分
       ↓
任务能自动判吗？
├─ 能 -> 检查测试覆盖、投机路径、隐藏测试
└─ 不能 -> rubric + 多裁判 + 人类抽查 + 顺序/长度偏差检查
       ↓
结果稳吗？ -> 置信区间、分层、重复、失败案例
       ↓
结果有效吗？ -> 与真实目标/外部效标核验
```

### 17.5 最终报告不要只给平均数

至少同时给：

- 总体与类别分层；
- 样本数和区间；
- 成本、延迟、token 和工具调用；
- pass@1 与允许重试的结果；
- 拒答、违规和失败类型；
- 模型+scaffold+版本；
- 已知污染和无法验证边界。

## 18. 公式卡：每个数字到底怎么算

### 18.1 Accuracy、error rate、分组平均


```math
\text{accuracy}=\frac{\text{答对数}}{\text{总题数}},\qquad
\text{error rate}=1-\text{accuracy}.
```

80/100 对：accuracy=0.8，error=0.2。

若 A 类 90 题准确率 90%，B 类 10 题准确率 10%：

- 按样本加权总准确率：$`(90\times0.9+10\times0.1)/100=82/100=82\%`$；
- 类别宏平均：$`(90\%+10\%)/2=50\%`$。

**Macro average（宏平均）** 让每类等权；**micro/sample-weighted average（微平均/样本加权）** 让每个样本等权。必须说明口径。

### 18.2 Confusion matrix、precision、recall

对“危险请求”二分类：

- TP：危险且被拦；FP：安全却被拦；
- FN：危险却放行；TN：安全且放行。


```math
\text{precision}=\frac{TP}{TP+FP},\qquad
\text{recall}=\frac{TP}{TP+FN}.
```

若 TP=80, FP=20, FN=10, TN=90：precision $`=80/100=80\%`$，recall $`=80/90\approx88.89\%`$。precision 问“拦下的有多少真危险”；recall 问“真危险中拦了多少”。

### 18.3 平均 NLL 与 PPL


```math
\overline{\mathrm{NLL}}=-\frac1T\sum_t\ln p_t,
\qquad
\mathrm{PPL}=e^{\overline{\mathrm{NLL}}}.
```

若平均 NLL 从 2 降到 1.8，PPL 从 $`e^2=7.389`$ 降到 $`e^{1.8}=6.050`$。NLL 少 0.2，不是 PPL 也少 0.2。

### 18.4 Elo


```math
P(A>B)=\frac1{1+10^{(R_B-R_A)/400}}.
```

- 同分：50%；
- A 高 400：$`1/(1+0.1)=90.91\%`$；
- A 低 400：$`1/(1+10)=9.09\%`$。

### 18.5 标准误和粗略区间


```math
SE\approx\sqrt{\frac{\hat p(1-\hat p)}n},\qquad
95\%\text{ rough CI}\approx\hat p\pm1.96SE.
```

这个公式假设样本近似独立且 $`n`$ 足够；成组题、重复用户或极小样本需 cluster/bootstrap，或 exact interval（精确二项区间：直接按二项分布尾概率求区间，不靠正态近似）等更合适方法。

### 18.6 pass@k

**口径 A：独立重试。** 每次成功率相同为 $`p`$，而且各次结果独立时：


```math
P(\text{至少一次成功})=1-(1-p)^k.
```

**口径 B：样本估计。** 先在同一 model、prompt、temperature 和预算下生成 $`n`$ 份可交换样本，其中 $`c`$ 份通过；再从这 $`n`$ 份中均匀、无放回地选大小为 $`k\le n`$ 的子集。总子集数是 $`\binom nk`$，全失败子集数是 $`\binom{n-c}{k}`$，所以：


```math
\mathrm{pass@}k=1-\frac{\binom{n-c}{k}}{\binom nk}.
```

若 $`n-c<k`$，全失败子集不存在，分子为 0，结果为 1。这里“无放回”只描述从已生成样本中选子集，不是语言模型的生成方式。任何 pass@k 都必须配 $`k`$、总预算、model/prompt/temperature、可交换假设和选择规则；自适应重试、看答案后再选、不同预算或强相关采样都不能不加说明地套这个估计式。

### 18.7 成本和 goodput

**Throughput（吞吐）** 是单位时间完成的总请求数；**goodput（有效吞吐）** 是同时满足质量、延迟和安全门槛的请求数。

60 秒完成 120 个请求，throughput $`=120/60=2`$ 请求/秒。若只有 90 个满足全部门槛，goodput $`=90/60=1.5`$ 请求/秒。

### 18.8 一个总分的单位危险

把 accuracy（百分比）与 cost（元）直接相加没有自然单位。若必须做效用：


```math
U=v_{success}\times P(success)-\text{cost}-\text{expected harm},
```

要公开每个价值系数和假设，并做 sensitivity analysis（敏感性分析，即改变假设看结论是否翻转）。

## 19. 常见误区：错误 → 为什么错 → 正确说法

| # | 错误说法 | 为什么错 | 正确说法 |
|---:|---|---|---|
| 1 | 分数就是模型真实智力 | 构念不能被单一任务直接观察 | 分数是特定协议下的证据 |
| 2 | 榜一就是所有用途最好 | 用途、成本、人群和风险不同 | 先写部署目标再选指标 |
| 3 | 使用量大证明能力强 | 可见度、价格和产品入口会影响采用 | adoption 与 capability 分报 |
| 4 | 偏好胜率高就更正确 | 用户可能偏爱长、顺耳、自信答案 | 单独核验事实与偏好 |
| 5 | 成本低就是效率高 | 便宜系统可能失败更多 | 报每次成功成本和 goodput |
| 6 | PPL 是平均概率 | 它是平均 NLL 的指数/概率倒数几何平均 | 按 §4 公式计算 |
| 7 | PPL 低 1 就固定好 1 个单位 | 指数尺度不是线性 | 同时报平均 NLL 和 PPL |
| 8 | 不同 tokenizer 的 PPL 可直接比 | token 数和单位变了 | 固定 tokenizer 或改用共同 byte 口径 |
| 9 | PPL 低必然事实更真 | PPL 奖励像数据，不验证事实 | 另做事实性评测 |
| 10 | OOD 数据一定没进训练 | 公开互联网可能重叠 | 把 OOD 与污染证据分开 |
| 11 | conditional PPL 分母含 prompt | 条件评测只平均被评分 response token | 分母用 (|y|) |
| 12 | 四选 25% 与十选 25% 一样强 | 随机基线分别 25% 和 10% | 报选项数和超随机幅度 |
| 13 | 难 benchmark 必然现实 | 可以造极冷门但无用的问题 | 分开难度与生态效度 |
| 14 | MMLU 等于全部语言理解 | 主要是固定考试型知识/推理 proxy | 明确 construct coverage |
| 15 | CoT 分数是裸模型能力 | prompt、解码和推理预算属于协议 | 报告完整 CoT 设置 |
| 16 | 饱和说明问题已解决 | 可能只是尺子区分力不足 | 换更有区分力且有效的任务 |
| 17 | 96% 一定胜 95% | 样本误差可能大于 1 点 | 报区间和配对差异 |
| 18 | Arena Elo 是绝对单位 | 平移所有 rating 不改变胜率 | 只解释相对差和版本 |
| 19 | Elo 高 100 就高 100% | 分差经 logistic 公式映射 | 代公式算概率 |
| 20 | A/B 匿名消除所有偏差 | 长度、位置和用户知识仍影响 | 随机位置并分解 rubric |
| 21 | 高相关证明 judge 有效 | 共同偏差也会产生相关 | 与外部效标、错误案例一起验证 |
| 22 | Length control 消除所有长度影响 | 回归只处理建模到的关系 | 保留残余混杂警告 |
| 23 | LLM judge 比人类客观 | judge 也有训练偏见和提示敏感性 | 多 judge + 人类抽查 |
| 24 | Agent 分数只属于 LM | scaffold、工具和预算直接改变成功率 | 报“模型+系统” |
| 25 | pass@5 可和 pass@1 直接排 | 五次机会消耗更多预算 | 同 $`k`$ 同预算比较 |
| 26 | 测试通过说明补丁完全正确 | 测试不覆盖的行为仍可能错 | 审计测试与代码 |
| 27 | 隐藏测试不会被利用 | 评分器、环境和数据仍可能有漏洞 | 沙箱、trace 审计和人工复查 |
| 28 | 同模型必有同 agent 分 | scaffold 和工具版本会变 | 锁定完整运行栈 |
| 29 | ARC-AGI 完全没有知识 | 接口、视觉和搜索仍需先验 | 说“尽量减少知识依赖” |
| 30 | 人类可解就测到全部智力 | 任务覆盖仍很窄 | 只解释被抽样的能力 |
| 31 | 拒答越多越安全 | 正常请求误拒会很高 | 同报漏拦与误拦 |
| 32 | 安全规则全球完全相同 | 法律、规范和上下文不同 | 报政策与地区边界 |
| 33 | Safety 只防恶意 prompt | 幻觉、迎合、差异影响也可能伤害 | 做多风险评测 |
| 34 | 公开攻击细节越多评测越科学 | 会扩大滥用能力 | 受控披露、保留可审计证据 |
| 35 | 真实用户数据必然最好 | 隐私、同意和不可复现是重大代价 | 做脱敏、聚合和治理 |
| 36 | Ground truth 永远正确 | 人工标签也会错或有争议 | 抽样双标与裁决 |

## 21. 自测答案

### 21.1 第 1–20 题

1. “好”可能指能力、成本、偏好、安全或采用率，是抽象 construct；metric 必须规定任务、数据、协议和计算法，例如“固定 100 题 accuracy”。

2. capability→MMLU accuracy；cost→每 1000 请求费用；preference→匿名 A/B 胜率；adoption→某时间窗的 token 或请求使用量。四者不能互相替代。

3. A：$`0.7\times90+0.3\times48=63+14.4=77.4`$。B：$`0.7\times86+0.3\times52=60.2+15.6=75.8`$。权重改变可能改变排序。

4. 序列概率用乘法：$`0.8\times0.5=0.4`$。

5. 计算器得 $`-\ln0.5=0.6931`$，$`-\ln0.25=1.3863`$。因为 $`0.25=0.5^2`$，$`-\ln0.25=-2\ln0.5=1.3862`$，约两倍。

6. NLL $`=0.6931+1.3863=2.0794`$。平均 NLL $`=2.0794/2=1.0397`$。PPL $`=e^{1.0397}\approx2.828`$。也可算 $`\sqrt{2\times4}=\sqrt8`$。

7. 每步概率都 0.2，倒数都 5；几何平均仍是 5。或平均 NLL $`=-\ln0.2=\ln5`$，PPL $`=e^{\ln5}=5`$。

8. conditional PPL 问“给定 prompt 后，回答 token 预测得怎样”。prompt 只作为条件，不是被评分目标，所以平均只除回答的 $`|y|=2`$。

9. 不能。tokenizer 改变 token 数、词表和每项概率含义。要固定 tokenizer/文本/预处理，或改成共同 byte/character 口径再谨慎比。

10. $`-[0.5\ln0.8+0.5\ln0.2]`$。$`ln0.8=-0.2231,ln0.2=-1.6094`$，所以 $`-[-0.11155-0.8047]=0.91625\approx0.9163`$。

11. 算术平均 $`(2+8)/2=5`$。几何平均 $`\sqrt{2\times8}=\sqrt{16}=4`$。

12. 原 PPL $`=e^2\approx7.389`$；新 PPL $`=e^{1.8}\approx6.050`$。下降约 $`7.389-6.050=1.339`$，不是 0.2。

13. 四选 $`1/4=25\%`$；五选 $`1/5=20\%`$；十选 $`1/10=10\%`$。

14. 四选：$`40\%-25\%=15`$ 个百分点。十选：$`40\%-10\%=30`$ 个百分点。

15. accuracy $`=83/100=83\%`$。error rate $`=17/100=17\%`$，也等于 $`1-0.83=0.17`$。

16. $`SE=\sqrt{0.8(0.2)/100}=\sqrt{0.0016}=0.04`$。余量 $`1.96\times0.04=0.0784`$。粗略区间 $`0.8\pm0.0784=[0.7216,0.8784]`$。

17. 100 题只差 1 题；抽样误差、题目相关、评分噪声都可能让顺序翻转。应做配对比较、报告区间并在新题上复验。

18. MMLU 是短、多选、固定学科题；律师工作还含检索、事实调查、长文写作、沟通、工具、时效和责任。高分只支持被覆盖的考试构念。

19. $`R_A=R_B`$，指数为 0，$`10^0=1`$，胜率 $`1/(1+1)=0.5=50\%`$。

20. A 高 200，$`(R_B-R_A)/400=-200/400=-0.5`$。$`10^{-0.5}\approx0.3162`$。胜率 $`1/(1+0.3162)=0.7597\approx76\%`$。

### 21.2 第 21–40 题

21. 经验胜率 (0.7)。分差 $`400\log_{10}[0.7/(1-0.7)] =400\log_{10}(2.3333)`$。$`log_{10}2.3333\approx0.368`$，所以约 (147.2) 分。样本小，区间会宽。

22. 不能。比较图有 A-B 与 C-D 两个不连通分量；各组内可定相对差，组间整体平移任意，A-C 无共同尺度。

23. 任三项：长度、排版、语气、自信程度、品牌残留、迎合、左右位置、用户是否知道事实。它们会影响“喜欢”而不等于“正确”。

24. 对同一用户问题和同一对答案，随机一半显示 A 左/B 右，另一半 B 左/A 右；比较原答案在两种位置的胜率。若差很多，说明位置偏差。

25. 回归只能控制已建模的长度关系；长度和题型、信息量、风格可能非线性互动，还有未观察混杂。因此它降低偏差，不证明为零。

26. 示例：固定 judge 版本和 prompt；随机左右顺序；允许 tie；按题型抽样做人类双评；另可查长度偏差、不同 judge 分歧和事实错误。

27. 可拆为：恰好 3 项；每项确实是建议；每项明确写风险；与用户条件相关；若有字数约束再单列。每项分别打分，便于定位失败。

28. 每次都多 5 cm，重复结果稳定，所以 reliability 高；固定多出的 5 cm 是 systematic bias，说明绝对测量不准确。但 criterion validity 要先指定“要预测哪个外部效标”，尺子例没有给出这个效标，因此不能仅凭它判定 criterion validity。低效标效度的例子：冷门 trivia 分数很稳定，却不能预测真实客服任务是否成功。

29. LM→生成计划的语言模型；scaffold→失败后重试循环；tools→终端或搜索；environment→固定容器/代码仓库。四者共同决定 agent 表现。

30. 三次全失败 (=(1-0.2)^3=0.8^3=0.512)。至少成功一次 $`=1-0.512=0.488=48.8\%`$。

31. 失败样本有 $`n-c=10-2=8`$ 份。总的 3 元子集数是 $`\binom{10}{3}=10\times9\times8/(3\times2\times1)=120`$；全失败子集数是 $`\binom{8}{3}=8\times7\times6/(3\times2\times1)=56`$。所以 pass@3 $`=1-56/120=64/120=0.5333=53.33\%`$。这里“无放回”是从已经生成的 10 份中均匀选一个 3 元子集，不是说 LM 生成 token 或答案时无放回。公式还要求样本来自相同协议并可交换。

32. pass@5 给五次机会，耗更多 token、时间和费用；pass@1 只有一次。必须同 $`k`$、同选择规则、同总预算，或画质量—成本曲线。若重试会读取先前错误、各样本预算不同、混用 model/prompt/temperature，或样本不再可交换，就不能把它们当作同一批可交换样本直接套组合数公式。

33. 补测输入原数组在调用前后相等；再测重复值、空数组、稳定性和异常输入。核心是覆盖“不得修改输入”的需求。

34. Trace 显示每一步工具、错误、重试和修改，可分辨能力、运气、测试投机、危险行为，以及失败来自 LM 还是 scaffold；最终一位 bit 看不到这些。

35. SWE-bench：输入仓库+issue，输出 patch，以测试通过为主。MLE-bench：输入数据+竞赛说明+环境，输出 submission 文件，以竞赛 metric/可执行结果为主。

36. 四选随机概率 $`1/4`$。80 题期望正确 $`80\times1/4=20`$ 题。期望不是保证每次恰好 20。

37. 按已知规则，第 2 列移到第 3 列。若已在最后一列，训练例没说明越界行为；需要“环绕、停留、删除或扩展”等边界规则证据，不能猜。

38. 会得到针对现有模型失败模式的困难分布，夸大其在普通任务中的普遍性；新模型的进步也可能只针对筛选规则。应标为 challenge set，不说代表全部使用。

39. 真危险+拦=TP；真安全+拦=FP；真危险+放=FN；真安全+放=TN。

40. 漏拦率 $`FN/(TP+FN)=5/100=5\%`$。误拒率 $`FP/(FP+TN)=20/200=10\%`$。分母分别是真危险总数和真安全总数。

### 21.3 第 41–60 题

41. 安全研究要让结果可审计，但公开可直接复制的攻击字符串会降低滥用门槛、伤害真实用户。应公开威胁模型、总体方法、成功率和修复证据，把高风险细节交给受控复核者。

42. 在设计良好的情况下，真实临床任务通常 ecological validity 更高，因为它包含病历、工具、多轮沟通和后果；选择题更容易自动评分，却只抽到很窄的知识行为。真实不自动等于标签正确或安全。

43. 三项示例：获得同意并只收必要字段；在进入评测前脱敏、聚合并限制小单元输出；把原始数据放在访问受控环境，只导出统计和经审计样例。还应设保留期限和删除流程。

44. Recall 的分母是真实目标 1000：
    $`\mathrm{recall}=900/1000=0.9=90\%.`$
    Precision 的分母是所有预测为目标的 $`900+50=950`$：
    $`\mathrm{precision}=900/950\approx0.94737=94.74\%.`$

45. 每次重测都得到近似分数，说明信度高；但冷门 trivia 与目标职业或真实决策关系弱，所以构念效度低。稳定地量错东西仍然是错。

46. 已知有相同原文，所以是 overlap 的证据。模型答错不能证明 memorization；若能逐字复现罕见错误或答案，才是更强记忆行为证据。

47. 这是 contamination：测试答案进入 prompt 调参过程，测试集不再是独立评价。还可能叫 test-set overfitting，但不能误称传统训练集 overfitting。

49. 网页可被提前复制、延后标日期、更新内容，评测题也可能在私有数据中出现。应结合抓取记录、内容哈希、训练数据审计和行为测试。

50. 样本问题率：
    $`8/100=8\%.`$
    它不是全体精确问题率，但显示标签噪声量级可能远大于 1 个百分点的榜差；应扩大审计、修题并报告修前修后排序。

51. A 类答对 $`90\times0.9=81`$，B 类答对 $`10\times0.1=1`$。Micro：
    $`(81+1)/(90+10)=82/100=82\%.`$
    Macro：
    $`(90\%+10\%)/2=50\%.`$

    $`80/(80+20)=80/100=80\%.`$
    Recall：
    $`80/(80+10)=80/90\approx88.89\%.`$

    $`120/60=2\text{ requests/s}.`$
    Goodput：
    $`90/60=1.5\text{ qualified requests/s}.`$

    $`U_B=100(0.8)-5-1=80-6=74.`$

    $`60/40=1.50\text{ 元}.`$

### 21.4 第 61–80 题

61. 任八项：决策目的、construct 与不测范围、目标人群/情境、数据来源和日期、运行协议、主次指标、预算/成本、不确定性、污染检查、失败案例、版本环境。

62. 总样本：
    $`300+100+50+50=500.`$
    各类正确数：
    $`300(0.95)=285,\quad100(0.8)=80,\quad50(0.6)=30,\quad50(0.4)=20.`$
    共 $`285+80+30+20=415`$，micro：
    $`415/500=83\%.`$
    Macro：
    $`(95+80+60+40)/4=275/4=68.75\%.`$

63. Leaderboard 提供受控、可重复的初筛；真实 pilot 检查自己的用户、工具、成本、隐私和错误后果。产品环境与 benchmark 分布不同，所以前者不能替代后者。

64. 随机准确率 $`1/10=10\%`$。200 题期望正确：
    $`200/10=20.`$

65. 模型可能输出“答案是 $`B`$，因为……”而抽取器只接受单独的 B，或标签顺序/大小写解析不同。知识相同，格式协议不同就会被判不同；应预先规定 parser 并审计 parse failures。

66. 至少报告：是否要求 CoT、最大推理 token、temperature/采样次数、答案抽取规则、few-shot 示例、是否可用工具、是否多数投票，以及推理成本。

67. 平局 20 场各分一半，即各加 10。A 等效得分：
    $`45+10=55.`$
    B：
    $`35+10=45.`$
    两者合计 100。

68. 模型集合、用户 prompt、人群、版本和拟合基准会漂移；Elo 还是相对尺度。没有共同比赛和同一拟合协议，跨日期分数差不一定是能力变化。

69. 固定硬件和每请求预算，分别在相同并发数 $`1,2,4,\ldots`$ 下测质量、P95 latency、吞吐和 goodput；比较整条 quality-latency-throughput 曲线，不能拿 A 的并发 64 对 B 的并发 1。

70. 不一定。pass@10 可因更多尝试提高，即使 pass@1 不变；它反映“给十次预算后至少一次成功”。应同时报 pass@1、pass@10 和成本。若第 2 次会读取第 1 次错误并改策略，十次结果有先后依赖，也不再是“同协议下交换编号不影响分布”的可交换样本，因此不能直接套样本版组合数公式；应把它报告为一个有状态、固定总预算的 agent protocol。

71. ARC-AGI 只抽样彩色网格/互动任务；仍依赖视觉、接口、搜索和程序先验，也不测事实、沟通、安全、长期现实规划。高分是这套任务上的证据。

72. 研究上下文可评是否给高层解释并避免危险细节；防御上下文可评授权环境中的检测和修复能力；恶意上下文重点评拒绝、降级和安全引导。协议要记录授权、用户身份和环境，不能只看相同字串。

73. 任三项：专业交付物难自动判；需资深专家且成本高；材料含商业/个人隐私；工具和文件格式难固定；任务随行业更新；可复现性较弱。

74. 优点：降低直接泄漏和针对题目调参。缺点：外部研究者难审计题质与复现；必须信任持有方的数据治理和评分实现。私有也可能有错题。

75. 审计只覆盖当时发现的问题；任务、依赖、测试和模型都会变，也可能仍有漏测。版本和限制让别人知道结论适用哪一份数据。

76. 三栏分别报告：正确性（总体/分层准确率及 CI）；成本（每请求、每成功请求费用与 P95 延迟）；安全（漏拦率、误拒率、严重度和人群切片）。不做加权总分，让决策者按门槛筛选。

77. 先按预注册规则随机抽失败，再按类别、严重度、成本异常和系统版本分层抽样；另审计 near-miss、最常见失败和高风险失败。报告抽样分母，避免只挑戏剧性截图。

78. 示例链：
    1. construct：在给定病历中提供安全、循证的下一步建议；
    2. population：某科室、某语言、明确疾病范围；
    3. task：脱敏真实病历加固定资料库；
    4. protocol：允许检索一次、禁止外网、同 token 预算；
    5. metrics：专家 rubric、关键遗漏率、伤害率、校准、成本；
    6. reliability：双专家盲评和分歧裁决；
    7. validity：与真实临床流程的小规模 pilot 对照；
    8. boundary：不把 benchmark 分数当诊疗许可。

79. 能力：政策正确、任务解决、工具成功；成本：每请求/每成功请求费用、P50/P95 延迟；风险：漏拦、误拒、隐私泄漏、升级率；人群切片：语言、问题类别、复杂度、新老用户和高风险群体。还要固定模型、scaffold 与预算。

80. 评测规则一旦公开，系统会针对可计分行为优化；可计分行为与 construct 不完全重合，于是出现刷分路径；开发者必须更新数据、规则和审计，新的规则又会成为下一轮优化目标。

### 25.2 一手论文与官方项目

这些来源用于核对 benchmark 定义和边界，不用于制造“当前排行榜”：

- [GPT-2](https://arxiv.org/abs/1901.02860)、[LAMBADA](https://arxiv.org/abs/1606.06031)、[HellaSwag](https://arxiv.org/abs/1905.07830)：PPL、长上下文补词与对抗续写。
- [MMLU](https://arxiv.org/abs/2009.03300)、[MMLU-Pro](https://arxiv.org/abs/2406.01574)、[GPQA](https://arxiv.org/abs/2311.12022)、[Humanity's Last Exam](https://arxiv.org/abs/2501.14249)：考试型评测的原始设计。
- [Chatbot Arena](https://arxiv.org/abs/2403.04132)、[AlpacaEval 2](https://arxiv.org/abs/2404.04475)、[WildBench](https://arxiv.org/abs/2406.04770)：成对偏好、长度控制和 LLM judge。
- [SWE-bench](https://arxiv.org/abs/2310.06770)、[SWE-bench Verified 的官方说明](https://openai.com/index/introducing-swe-bench-verified/)、[Terminal-Bench](https://arxiv.org/abs/2601.11868)、[CyBench](https://arxiv.org/abs/2408.08926)、[MLE-bench](https://arxiv.org/abs/2410.07095)：agentic evaluation。
- [ARC Prize 官方任务说明](https://arcprize.org/arc-agi)：ARC-AGI 系列。具体模型成绩仍是按日期变化的快照。
- [HarmBench](https://arxiv.org/abs/2402.04249)、[AIR-Bench](https://arxiv.org/abs/2407.17436)、[GCG](https://arxiv.org/abs/2307.15043)：safety benchmark 与 automated red-teaming。对 GCG 只讲评测原理与防御边界，不给可执行攻击步骤。
- [GDPVal](https://arxiv.org/abs/2510.04374)、[MedHELM](https://arxiv.org/abs/2505.23802)、[Clio](https://arxiv.org/abs/2412.13678)：现实工作、医疗和隐私保护的评测框架。
- [Detecting Pretraining Data from Large Language Models](https://arxiv.org/abs/2310.17623)：exchangeability 检测；[Benchmarking Transparency](https://arxiv.org/abs/2410.08385)：报告训练评测重叠；[SWE-bench Goes Live!](https://arxiv.org/abs/2502.03461)：Platinum/实时软件任务口径；[Docent 官方介绍](https://transluce.org/introducing-docent)：agent trace 审计。

### 25.3 哪些结论不能从这些来源推出

1. 一篇 benchmark 论文不能证明它完整测到了“智能”。
2. 某榜高分不能自动推出产品更便宜、更安全、更适合你的用户。
3. 与人类评分相关不能自动推出 judge 没有长度、风格或群体偏差。
4. private/fresh 数据能降低直接调参风险，但不能保证零污染、零错题。
5. agent 分数不能归因给裸 LM；scaffold、工具、环境、预算和版本也是因果链一部分。
6. 课程里的 2026 图表只说明当时、该规则、该模型集合下的观察；本笔记不声称提供实时名次。
7. 外部远程图片打不开时，笔记明确披露，绝不从模糊缩略图猜数字。

### 25.4 本地验证边界

- 公式与小数字例在本地独立复算；没有调用商业模型 API 重跑所有 benchmark。
- 没有访问 benchmark 的私有测试集，因此不声称重新验证 leaderboard 成绩。
- 远程网页和排行榜会更新；引用链接用于回查项目定义，不保证页面未来布局不变。
- 安全部分只做非操作性的评测教育，不复现高风险 prompt 或攻击载荷。

1. **问目的**：采购、科研、开发反馈、影响还是安全？
2. **写 construct**：你真正想知道的能力或风险是什么？
3. **写对象**：评 method、裸 model，还是 model+scaffold+tools 的 system？
4. **看样本**：来自谁、哪个日期、什么语言、是否代表目标人群？
5. **看协议**：prompt、few-shot、CoT、工具、重试、token/时间预算是否一致？
6. **重算 metric**：分母、随机基线、micro/macro、平局、失败和成本怎样算？
7. **看不确定性**：样本量、置信区间、配对差异、版本漂移和多次运行。
8. **查可刷路径**：污染、风格、长度、测试漏洞、答案抽取、额外预算。
9. **审计失败**：随机+分层看错误和 trace，不只看平均分或最戏剧性截图。
10. **回到真实决策**：在自己的用户和环境做 pilot，报告质量—成本—风险三轴。

### 26.2 你现在应该能独立完成

- 从序列概率推到 NLL、平均 NLL、PPL，并手算 tiny 例；
- 解释 tokenizer、数据与条件口径为何让不同 PPL 不可直接比；
- 计算多选随机基线、accuracy、precision、recall、置信区间近似和 pass@k；
- 从成对结果计算 Elo 胜率，并说明 Elo 是相对尺度而非绝对智力；
- 区分 reliability、construct validity、criterion validity、difficulty、discriminative power 和 ecological validity；
- 判断一个 agent benchmark 到底测了模型、scaffold、工具还是完整系统；
- 区分 overlap、contamination 和 memorization，正确解释 exchangeability 只是一种线索；
- 发现 unit test、答案抽取、长度偏差、预算不公平和 leaderboard snapshot 等陷阱；
- 设计一张 evaluation card，并把能力、成本、安全和人群切片分开报告；
- 在看见“某模型榜一”时，先追问证据链，而不是立即把它翻译成“最适合我”。

### 26.3 最后一条因果链

    抽象目标
      -> 选样本、任务与协议
      -> 得到一个有条件的指标
      -> 检查信度、效度、现实性、污染、预算和失败
      -> 才形成对某个具体决策有用的证据

如果只记一句：**评测不是寻找一个神奇总分，而是让“我要做什么决定”与“这个数字究竟证明了什么”保持一致。**
